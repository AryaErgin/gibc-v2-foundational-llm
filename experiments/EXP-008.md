# EXP-008 — Near-Cap GELU versus SwiGLU Ablation

## Scientific question

With all EXP-007B and EXP-004 controls frozen, does a parameter-near-matched SwiGLU MLP improve the final combined frozen general/Edu validation loss enough to replace Near-Cap Architecture Recipe v2?

EXP-007B is the existing control: vocabulary 8,192; d_model 640; 9 layers; 20 heads of head dimension 32; GELU MLP d_ff 2,560; exact count 49,491,840.

EXP-008A changes only the MLP: three bias-free SwiGLU projections with SiLU gating and d_ff 1,728. It retains tied input/output embeddings, RMSNorm, RoPE, standard causal MHA, no bias/dropout, context 512, and the same initialization policy where structurally applicable.

## Independent parameter calculation

The candidate count is derived rather than copied: embedding `8192*640 = 5,242,880`; attention `9*4*640*640 = 14,745,600`; SwiGLU MLP `9*3*640*1728 = 29,859,840`; norms `9*2*640 + 640 = 12,160`; tied output additional `0`. Total: **49,860,480** trainable parameters, which is 139,520 below the 50,000,000 cap.

## Frozen controls and authorization

EXP-008A reads the exact first 300,023,808-token EXP-004 non-cycled stream, SHA-256 `8e727fa2a2614751a1c34d7f9ac411dfebeb379a09f584ba4f7f418d1059cea1`, with the frozen tokenizer and general/Edu validation hashes. It uses seed 42; BF16 autocast with FP32 model/optimizer state; AdamW betas 0.9/0.95 and eps 1e-8; matrix decay 0.1; clip 1.0; peak/min LR 6e-4/6e-5; 100 warmup updates; 9,156-step cosine horizon; fixed 32 sequences x 2 accumulation; and the same checkpoints/dual-validation intervals (3,052 / 6,104 / 9,156).

Native Windows, OMEN Performance mode, and original AC power are frozen as the standard training environment unless a reproducibility problem occurs. SYS-001 rejected 64x1 and all related timing/cache/fused changes for the production path; they must not be enabled here.

The 60-update preflight passed at implementation commit `c6638df2864cde16e91f3c00b705c35af92be69a`, including a fresh-process one-update resume from step 60 to step 61 at the exact sequential cursor. Exact evidence is in `results/EXP-008-preflight.md`. One full 9,156-update / 300,023,808-token EXP-008A run is authorized. Official benchmarks, control retraining, LR changes, EXP-009, and all training beyond 300M are not authorized.

## Predeclared decision

Primary metric: `combined_validation_loss = (general_validation_loss + educational_validation_loss) / 2` at equal 300,023,808 tokens.

* SwiGLU advantage at least 0.02 nats: SwiGLU capability winner.
* Absolute difference below 0.02 nats: engineering tie resolved by throughput, VRAM, implementation simplicity, and parameter efficiency.
* GELU advantage at least 0.02 nats: retain EXP-007B.
