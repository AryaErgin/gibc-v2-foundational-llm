# EXP-009 — Near-Cap Learning-Rate Calibration

## Question

For frozen Near-Cap Architecture Recipe v3, is the inherited `6e-4` peak learning rate appropriate at the controlled 300,023,808-prediction-token horizon?

## Frozen control

The existing EXP-008A result is the control and is not retrained: peak/min learning rate `6e-4` / `6e-5`, 100-update warmup, and cosine decay over exactly 9,156 updates. Its frozen final general/Edu/combined validation losses are `3.5561715066` / `3.2465001345` / `3.4013358206`.

Recipe v3 remains exact: vocabulary 8,192; d_model 640; 9 layers; 20 heads of head dimension 32; bias-free SiLU-gated SwiGLU d_ff 1,728; tied embeddings/output; RMSNorm; RoPE; standard causal MHA; no bias/dropout; and exactly **49,860,480** trainable parameters.

## Candidates and controls

EXP-009A changes only the schedule amplitude to peak/min `4e-4` / `4e-5`. EXP-009B changes only the schedule amplitude to peak/min `8e-4` / `8e-5`. Both retain the 10:1 ratio, 100-update warmup, and 9,156-update cosine shape.

Both candidates retain the exact frozen first 300,023,808-prediction-token EXP-004 non-cycled stream (SHA-256 `8e727fa2a2614751a1c34d7f9ac411dfebeb379a09f584ba4f7f418d1059cea1`); tokenizer and validation hashes; general and Edu validation tensors; data order; context 512; seed 42; BF16 autocast with FP32 parameters and optimizer state; AdamW betas 0.9/0.95, eps 1e-8, matrix decay 0.1; gradient clipping 1.0; physical batch 32 x 2 accumulation; 32,768 effective prediction tokens/update; and checkpoint/dual-validation intervals 3,052 / 6,104 / 9,156. The environment remains native Windows, OMEN Performance mode, and original AC power.

## Preflight and decision rule

Each candidate must first pass a bounded 60-update finite-loss preflight and a fresh-process one-update checkpoint resume. If both are stable, each is separately authorized for exactly one 9,156-update / 300,023,808-token run. Early losses are not a selection signal.

The primary metric is `combined = (general + Edu) / 2`, compared with the existing `6e-4` control. A candidate advantage of at least `0.01` nats wins subject to the split guard. An absolute difference below `0.01` nats is an engineering/statistical tie and retains `6e-4` to avoid proxy-horizon over-tuning. A candidate disadvantage of at least `0.01` nats rejects it. If a qualifying combined improvement makes either general or Edu worse by more than `0.02` nats, promotion is not automatic and requires research review.

No official benchmark, architecture/data/batch change, or training beyond these controlled 300M candidates is authorized.
