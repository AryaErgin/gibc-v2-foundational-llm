# EXP-001A Infrastructure Validation Design

## Purpose and boundary

EXP-001A establishes a transparent and reproducible pretraining path for the approved EXP-001 control. It is not an architecture, tokenizer, data-mixture, or hyperparameter search, and it must not start the approved 100,000,000-token training run.

The authoritative scientific configuration is the user-provided EXP-001A specification. `GIBCV2_EXTENDED_INSTRUCTIONS.txt` exists locally as non-versioned project guidance and is intentionally excluded from Git. The committed `AGENTS.md`, approved EXP-001A specification/design, and experiment records define the public engineering and scientific contract. The absence of a tracked `GIBC_LLM_MASTER_INSTRUCTIONS.txt` is not a blocker and does not justify creating a renamed copy of the ignored local file.

## Fixed model and objective

Implement one PyTorch decoder-only causal Transformer: vocabulary 8,192; width 256; eight blocks; eight heads of dimension 32; MLP width 1,024; GELU; pre-RMSNorm; RoPE; zero dropout; context length 512; bias-free linear layers; and tied input/output embedding weight. Attention uses native `torch.nn.functional.scaled_dot_product_attention` with `is_causal=True` and no `torch.compile`, Triton, custom CUDA kernel, GQA/MQA, MoE, or layer sharing.

The loss is next-token cross-entropy over packed sequences. An end-of-document special token is appended to each accepted document. Packed streams may predict the first token of the next document after an EOD token; this is intentional, because the EOD token preserves the boundary while avoiding padding waste. The expected trainable count is fixed at 8,392,960 and is a hard invariant, not an adjustable expectation.

## Components and interfaces

`src/gibc_llm/model.py` exposes typed configuration, RMSNorm, parameter-free RoPE, causal attention, Transformer blocks, and the tied-weight language model. It returns logits shaped `[batch, sequence, vocab]` and exposes an exact parameter breakdown.

`src/gibc_llm/data.py` deterministically assigns each source document from a stable content hash to train or validation, normalizes and screens training documents against benchmark n-grams, appends EOD tokens, packs a reproducible token stream into 512-token blocks, and serializes manifests/hashes. The full 100M/approximately-2M token targets and bounded EXP-001A targets are configuration values, not hard-coded code changes.

`src/gibc_llm/tokenizer.py` trains and serializes an 8,192-entry byte-level BPE from train documents only. The special-token set is kept minimal and counted within 8,192; tokenizer statistics and artifact hashes are emitted in the preparation manifest.

`src/gibc_llm/train.py` provides BF16 CUDA training with AdamW, fixed hyperparameters, cosine decay, 100-step warmup, gradient clipping, effective batches of 32,768 tokens, held-out validation, JSONL metrics, CUDA memory measurements, checkpoints, RNG persistence, and resume.

`src/gibc_llm/generation.py` provides greedy or top-k/temperature decoding for a checkpoint. `src/gibc_llm/evaluation.py` supplies a transparent likelihood/rolling-likelihood bridge to a pinned lm-evaluation-harness version without pretrained weights or changed task templates.

`scripts/` contains small CLI entry points for parameter counting, preparation, training, generation, and evaluation. Configuration, result manifests, and documentation connect each artifact to its Git commit, data revision, tokenizer hash, and seed.

## Data, provenance, and contamination

Preparation will resolve and record the official FineWeb Hugging Face repository, a manageable official configuration, immutable revision, license, and fields before materialization. It will fetch only the bounded document/token amount needed for tokenizer training, tests, and at most approximately two million smoke-training tokens.

The decontamination module will use a documented canonical text normalization and normalized 13-gram index built from the named benchmark material: HellaSwag, ARC-Easy, PIQA, WinoGrande, and WikiText-103 validation/test. It will reject a training document on overlap, report scanned/accepted/rejected counts and privacy-preserving document hashes/examples, and include synthetic overlap/non-overlap tests. It is a precaution rather than a claim that absence of matches proves zero contamination.

## Verification plan

Tests are written before each implementation unit and must first fail for the intended missing behavior. Required coverage includes exact parameter accounting, actual shared weight storage, causal non-leakage, target shift, tensor shapes, RoPE parameter absence, deterministic document assignment/token serialization, synthetic contamination rejection, checkpoint equivalence/resume, and a tiny-data overfit trajectory.

After unit tests, bounded hardware work will confirm BF16 CUDA stability, held-out loss/perplexity, checkpoint resume, generation, lm-evaluation-harness invocation on limited examples only, and measured throughput/VRAM. The smoke training budget remains no greater than approximately two million tokens. Any unavailable dataset/harness/API condition, warning, or failed check is reported rather than bypassed.

## Documentation and outputs

`ARCHITECTURE.md` maps mathematical parameter terms to code. `DATA_SOURCES.md` stores resolved FineWeb and benchmark provenance plus deterministic/decontamination protocol. `EXPERIMENT_LOG.md` and `experiments/EXP-001.md` remain explicitly in-progress/infrastructure-validated pending research-chat review. Run results are JSONL plus a small committed summary; raw data, caches, shards, checkpoints, and large results remain ignored.

## Risks and non-decisions

The precise FineWeb revision/configuration, pinned lm-evaluation-harness release, and benchmark dataset revisions are operational provenance to resolve from their official sources before data preparation; they are not scientific substitutions. GPU microbatch selection is measured from a small bounded set while preserving 32,768 effective tokens. No alternative model mathematics, tokenizer vocabulary, data source, or benchmark protocol is authorized by this design.
